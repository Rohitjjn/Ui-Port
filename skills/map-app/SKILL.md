# Map the app

One job: a compact, accurate map of the existing project, and the UI/engine split that every
later step depends on. The map is generated by a script, then reviewed — never written from
memory.

## Procedure

1. Generate the map and the protected-path proposal:

   ```
   node ${CLAUDE_PLUGIN_ROOT}/scripts/scan-app.mjs <projectRoot> \
     --json .uiport/maps/app-map.json \
     --md   .uiport/maps/app-map.md \
     --engine-paths .uiport/engine-paths.json
   ```

2. Read `.uiport/maps/app-map.md`. It contains, in this order: toolchain versions, modules,
   UI/engine file split, screens, navigation, ViewModels with the StateFlows they expose,
   DI modules, engine entry points, data models, and the proposed protected globs.

3. **Review the split before going further.** The protect hook will use
   `.uiport/engine-paths.json`. Check:
   - no `ui/` directory is protected as a whole (would block all porting work);
   - navigation and theme files are treated the way the user wants (default: theme is UI,
     navigation is engine because it is routed by the app shell);
   - generated code (`build/`), tests and resources are not protected.

   Edit `engine-paths.json` and say why in the worklog.

4. Summarise in the worklog: the toolchain versions (they decide which Compose APIs and which
   screenshot tool are safe), the engine entry points the new UI could call, and anything
   surprising (custom design system, non-standard navigation, multiple app modules).

5. For a large project, do not paste the whole map into the conversation. Read the sections
   you need, and reference file paths.

## Rules

- The map must be generated, not hand-written. If the script mislabels a file, fix the
  heuristics in `scripts/lib/scan-app.mjs` (with a unit test), not the output.
- Never read every Kotlin file into context. The scanner exists to prevent that.
- If the project has no engine (case 3), say so and skip to the design-document path in
  `wire-engine`.

## References

- `references/app-map-schema.md` — every field of `app-map.json`, so the agent can query it
  with `jq`-style reads instead of re-scanning.
- `references/engine-split.md` — how UI and engine are told apart, and the documented
